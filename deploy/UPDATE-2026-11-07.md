## Установка через уже настроенное защищённое подключение

1. Скопировать kwazar-update.patch на сервер, например в /tmp. Не передавать ключ владельца и пароли в чат.
2. В /opt/kwazar-site проверить ветку и отсутствие несохранённых изменений. Сохранить текущий SHA и резервную копию .env / .env.runtime в защищённом месте. Не заменять эти файлы.
3. До изменения выполнить резервную копию базы штатным backup_store.py:

```sh
cd /opt/kwazar-site
git status --short
git rev-parse HEAD
docker compose exec -T app python3 backup_store.py --data-dir /var/lib/kwazar --output-dir /tmp/pre-update
mkdir -m 700 -p /opt/kwazar-backups/pre-update-2026-11-07
docker compose cp app:/tmp/pre-update/. /opt/kwazar-backups/pre-update-2026-11-07/
```

Если каталог копии уже существует, выбрать новое имя. Убедиться, что копия действительно появилась. Резервная копия SQLite включает заявки и после этого обновления также цены. Файл admin-token хранится отдельно в существующем томе: том сохранять, ключ не пересоздавать.

4. Применить пакет, проверить изменения, собрать и запустить:

```sh
git apply --check /tmp/kwazar-update.patch
git apply /tmp/kwazar-update.patch
python3 -m unittest discover -s tests -v
docker compose build app
docker compose up -d --no-deps app
docker compose ps
curl --fail https://kwazar-led.ru/healthz
```

Не выполнять `docker compose down -v`, `docker volume rm` или пересоздание проекта с другим именем. Не менять KWAZAR_DATA_DIR, ключ и переменные оплаты.

5. В браузере проверить прежние заявки и вход с прежним ключом. Установить реальную цену одного товара, проверить каталог/карточку/корзину. После `docker compose restart app` повторить проверку. Проверить контакты, разделы и товар без цены. Сохранить изменения кода в Git после проверки.

## Откат кода

Если после применения патча дополнительных изменений не было:

```sh
git apply --reverse --check /tmp/kwazar-update.patch
git apply --reverse /tmp/kwazar-update.patch
docker compose build app
docker compose up -d --no-deps app
```

Том и базу при откате кода не трогать: старая версия игнорирует новую таблицу. Это сохраняет и новые заявки, поступившие после обновления. Восстановление старой базы без отдельной необходимости приведёт к потере таких заявок.
