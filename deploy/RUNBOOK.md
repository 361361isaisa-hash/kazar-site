# Размещение KWAZAR на VPS

Комплект рассчитан на небольшой магазин с заказами-заявками. Проверен локально через Docker Compose: веб-прокси → приложение → постоянный том SQLite, пересоздание приложения, создание и восстановление резервной копии. Реальный домен, сертификат публичного сайта и платежи в этой проверке не подключались.

Приложение сейчас использует собственный сервер на Python stdlib за Caddy. Это не проверка высокой нагрузки или аудит безопасности. Публичный запуск требует проверки на выбранном хостинге; для роста нагрузки планировать переход обработчиков на промышленный application server.

## Рекомендованный старт

- VPS в России, например Timeweb Cloud; обычный статический хостинг для этого приложения не подходит.
- 1–2 vCPU, 2 ГБ RAM, 20–30 ГБ постоянного SSD/NVMe, публичный IP.
- Ubuntu 24.04 LTS, Docker Engine и Docker Compose 2.24.4+.
- Зарегистрированный домен. `kwazar-led.ru` — выбранное владельцем имя; регистрацию и доступ к DNS ещё нужно подтвердить.

Точный тариф, публичный IP, диск и резервные копии оплачиваются по условиям провайдера. Покупку нужно согласовать до создания платных ресурсов. Пакет не создаёт сервер, не регистрирует домен и не отправляет файлы провайдеру сам.

## Подготовка сервера

1. Создать VPS в собственном аккаунте хостинга. Получить публичный IP через панель. Пароли и ключи не отправлять в чат.
2. Использовать официальный образ/установщик Docker от провайдера либо инструкции https://docs.docker.com/engine/install/ubuntu/ . Не запускать непроверенные скрипты установки.
3. Перенести исходники в отдельный каталог сервера. Не класть в публичные файлы `.env.runtime`, ключи, базу заказов или вложения из чата.
4. Для корня домена создать DNS-запись A на IP сервера. AAAA добавлять только для реально настроенного IPv6. Открыть входящие TCP 80 и 443; порт приложения 8000 наружу не публиковать. UDP 443 — для HTTP/3, не требуется для обычного HTTPS.
5. В каталоге проекта скопировать `deploy/.env.example` в `.env` и указать только настоящий зарегистрированный домен без протокола/пути. Оставить оплату выключенной.

```sh
cp deploy/.env.example .env
# Убедиться, что kwazar-led.ru зарегистрирован на владельца и DNS направлен на сервер.
chmod 600 .env
docker compose config --quiet
docker compose up -d --build --wait --wait-timeout 120
```

Caddy автоматически запросит сертификат для домена после корректной настройки DNS и доступности портов. Не запускайте публичный профиль с чужим или примерным доменом.

Проверить в браузере HTTPS, главную, каталог, галерею, заявку, личную страницу заявки и кабинет владельца. На первом запуске использовать отдельную тестовую заявку с пометкой, без реальных платежей.

## Сервисы и данные

- `app` работает от UID 10001, с неизменяемой файловой системой и доступом на запись только к данным и временной директории. Приложение не публикует свой порт на хосте.
- `proxy` принимает HTTP/HTTPS, ограничивает размер тела и таймауты, передаёт запрос приложению. Административный API Caddy отключён.
- `backup` каждый час делает согласованный снимок SQLite, проверяет integrity и хранит последние 168 снимков (примерно 7 дней при штатной ежечасной работе).
- `orders` — постоянный том заказов и ключа владельца.
- `backups` — отдельный постоянный том копий.
- `caddy_data`/`caddy_config` — состояние TLS и конфигурации.

Docker автоматически перезапускает завершившиеся процессы. Состояние healthcheck само по себе не перезапускает работающий контейнер: подключить мониторинг у хостинга. `/healthz` возвращает только готовность приложения и хранилища, без клиентских данных. У backup есть проверка свежести копии: менее двух часов.

Резервный том находится на том же VPS. Он не защищает от потери всего сервера/аккаунта. После выбора хостинга настроить отдельную копию в другом защищённом хранилище; данные заказов и личные ссылки в копиях конфиденциальны. Команды ниже не удаляют базу или тома.

```sh
docker compose ps
docker compose logs --tail 30 app backup
docker compose exec -T backup python3 backup_store.py --data-dir /var/lib/kwazar --output-dir /backups
```

Ключ владельца создаётся в `/var/lib/kwazar/admin-token` внутри тома orders, если не задана защищённая переменная `KWAZAR_ADMIN_TOKEN`. Получать его через собственный защищённый доступ к серверу и вводить в `/admin.html`; не публиковать ключ в отчётах, переписке или Git.

## Обновления

Сначала сделать проверенную резервную копию. Затем перенести новые исходники и выполнить:

```sh
docker compose up -d --build --wait --wait-timeout 120
```

Имена проекта и томов должны оставаться теми же. Не использовать `down --volumes` на рабочем магазине: это удалит данные. Изменение каталога требует пересборки/перезапуска приложения, том orders сохраняется.

## Восстановление

Перед восстановлением сохранить текущее состояние, остановить app и backup (proxy можно оставить). Проверить копию через `PRAGMA integrity_check`, восстановить `orders.sqlite3` в существующий том с UID/GID 10001 и правами 0600. WAL/SHM старой рабочей базы не подмешивать к восстановленному снимку. Сохранить существующий ключ владельца либо задать новый через защищённую конфигурацию. Затем запустить app/backup и проверить личную страницу тестовой заявки. Клиентские ключи доступа хранятся в самой базе и сохраняются в копии.

Не проверять восстановление поверх единственной рабочей базы. В локальном тесте это выполняется на отдельной базе/томах и синтетических данных.

## Платежи и секреты

Для дополнительной конфигурации сервер может читать локальный `.env.runtime` (необязательный, исключён из Git и Docker context). Права файла — 0600. Реальные значения указываются только на сервере/в секретном хранилище хостинга, не в frontend и не в чате. Общий флаг включения платежей задаётся в `.env`, по умолчанию 0.

Активация ЮKassa, налоговые параметры чеков, реквизиты продавца и подтверждённые цены описаны в README.md. Пока они отсутствуют, магазин принимает заявки и ведёт к покупке на WB, но не списывает деньги с карты. Для ввода настоящих банковских данных используется только страница провайдера после настройки.

В облачной среде Codex Docker получает настройки сессионного прокси автоматически. Внутренний адрес `app` исключён из внешнего прокси только у Caddy через NO_PROXY. Внешние TLS-подключения контейнера в этой среде требуют отдельного доверия к CA согласно runtime skill; не отключать проверки сертификатов и не копировать сессионные CA/учётные данные в образ. Локальный deployment test не обращается к платёжным API или центру сертификации.

## Проверки до реального переноса

```sh
python3 -m unittest discover -s tests -v
node tests/browser.cjs
docker build -t kwazar-site:local .
KWAZAR_DOMAIN=kwazar.example docker compose config --quiet
python3 tests/deploy_smoke.py
```

`deploy_smoke.py` требует локальный Docker socket и Compose, создаёт свой проект/тома, отключает платежи и HTTPS только внутри тестового профиля, проверяет сохранность и восстановление синтетического заказа и удаляет только свои тестовые ресурсы. Производственный Caddyfile сохраняет HTTPS. Успех этих проверок не означает публикацию сайта или выпуск реального сертификата.
