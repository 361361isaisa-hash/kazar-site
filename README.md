# KWAZAR — automotive lighting

Сайт автомобильного света: товарный каталог, избранное, сравнение, заказ-заявка, кабинет владельца, информационные материалы и подготовленная интеграция ЮKassa.

## Запуск среды

В существующем checkout `/workspace/kazar-site`:

```sh
python3 server.py --bind 0.0.0.0 --port 8000
```

Для приложения — Python 3.12+, без сторонних runtime-зависимостей и сборки. Для импорта Excel и его тестов нужны openpyxl и Pillow из `requirements-import.txt` (в текущей среде уже установлены). Шрифт Manrope и изображения локальные. Не заменять этот запуск на `http.server`: для заявок нужен backend. Каждая облачная задача уже изолирована; Git worktree создавать только по явной просьбе.

База по умолчанию: `/workspace/kwazar-data/orders.sqlite3`, вне публичного checkout. Путь переопределяется через `KWAZAR_DATA_DIR`. Директория должна быть на постоянном диске. При первом запуске автоматически создаётся приватный файл `/workspace/kwazar-data/admin-token` с ключом владельца, если не задана переменная `KWAZAR_ADMIN_TOKEN`. Значение не выводится в журнал и не хранится в репозитории. Владелец получает ключ через защищённый доступ к файлу либо задаёт собственный ключ длиной не меньше 24 символов через защищённую конфигурацию сервера. Не отправлять ключи в чат и не публиковать их.

Кабинет `/admin.html` требует ключ; API без него не выдаёт заявки. Ключ в браузере владельца хранится только в памяти до выхода/перезагрузки. Ссылка клиента содержит отдельный непредсказуемый ключ во фрагменте URL; относиться к ней как к конфиденциальной. Нельзя получить чужую заявку по её номеру.

Сохраняются имя, контакт, город, комментарий, параметры автомобиля, состав запроса, согласие и статусы. Заявки сохраняются в SQLite, не в браузере. Данные карты не принимаются. Автоматические email/Telegram-уведомления не подключены; владельцу нужно проверять кабинет. Контакт сайта: 361isa@mail.ru.

## Каталог и заказы

`catalog.json` теперь содержит **53 реальные карточки** из предоставленного владельцем файла `02.11.2026_17.12_Все характеристики по предметам.zip` (лист «Товары», 2 ноября 2026). Во всех карточках указан бренд **KVAZARLAMP**; маркетинговое название сайта KWAZAR сохранено по указанию владельца. Импортированы названия, серия, цоколь, описания, характеристики, прямые ссылки WB и **514 оригинальных фотографий** в `assets/products/`. Исходный Excel не изменён.

Каталог показывает 12 товаров за раз, затем «Показать ещё». Есть поиск по названию, серии, артикулу, цоколю и алиасу, фильтры H/HB/D и LED/мини-линзы, сортировка по названию и мощности, избранное и сравнение. В модальном окне — полная галерея, описание, таблица характеристик, совместимость и два пути заказа. Мощность показана как в колонке выгрузки, без предположения «на лампу» или «на комплект»; нужно сверять описание. Цены и остатки в файле отсутствуют: `price` и `stock` равны null, не нулю. На сайте стоимость по согласованию; фактическую цену WB показывает карточка площадки.

`selection.json` сохраняет прежние справочные направления H1/H4/H7/H11/HB3/HB4 для заявок по автомобилю и совместимости со старыми корзинами. Сервер принимает и эти направления, и реальные товары. Название и артикул WB в заявке определяет сервер из каталога, а не присланный браузером текст или цена.

Покупатель добавляет направления в заявку или указывает автомобиль. Владелец согласует выбранный товар, комплектность, доставку и стоимость с клиентом, затем подтверждает их в кабинете. Клиент видит предложение на личной странице. На Wildberries можно купить товары прямо сейчас по ссылке магазина https://www.wildberries.ru/seller/3944663.

Сервер принимает только известные позиции и допустимые количества, проверяет контакт/согласие, защищает повторную отправку ключом идемпотентности. Платёжная сумма берётся только из подтверждённого серверного предложения. Файлы backend, база и ключи через статический сервер не выдаются.

## ЮKassa: подготовлено, не активировано

Пока договора/ключей нет, кнопка оплаты заблокирована. Реальные транзакции не проводились. Код и сценарии проверены с имитацией провайдера; это не банковская сертификация и не проверка живого эквайринга.

Для включения на HTTPS-хостинге нужно настроить через защищённую конфигурацию сервера:

- `KWAZAR_PUBLIC_URL` — публичный HTTPS-адрес сайта без завершающего `/`;
- `KWAZAR_YOOKASSA_SHOP_ID` — идентификатор магазина;
- `KWAZAR_YOOKASSA_SECRET_KEY` — серверный секретный ключ (никогда не в frontend или Git);
- `KWAZAR_RECEIPT_VAT_CODE` — соответствующий бизнесу код НДС по актуальной документации ЮKassa;
- `KWAZAR_TAX_SYSTEM_CODE` — соответствующий бизнесу код системы налогообложения;
- `KWAZAR_PAYMENTS_ENABLED=1` — включать только после настройки и проверки тестового магазина.

Налоговые параметры должен подтвердить владелец/бухгалтер. Настроить чеки, договор, реквизиты продавца и условия покупки/доставки/возврата до публичных продаж. Проверить выбранный способ секретов на реальном хостинге: Basic-auth к API требует работоспособной серверной пары shop ID / key.

Провайдер создаёт redirect-платёж с `capture=true`, чеком и ключом идемпотентности. Для чека используется согласованное наименование и общий комплект; если продаются отдельные позиции с разными налогами, до включения эквайринга расширить предложение и чек до отдельного списка позиций. В `KWAZAR_PUBLIC_URL` и чеках не должно быть фиктивных реквизитов.

Webhook в кабинете ЮKassa: `https://ВАШ-ДОМЕН/api/payments/webhook` для событий платежа. Сервер не доверяет уведомлению: повторно запрашивает платёж у ЮKassa, проверяет идентификатор, сумму, валюту, metadata и `paid`. То же происходит при обновлении страницы заказа. Простой возврат с платёжной страницы не означает оплату. После создания платежа стоимость блокируется; отмены/возвраты платежей через кабинет ЮKassa, отдельный интерфейс возвратов на сайте не реализован.

## Проверки

```sh
node --check app.js
node --check account.js
python3 -m unittest discover -s tests -v
node tests/browser.cjs
```

Последняя команда требует Chromium и Playwright, уже доступных в текущей облачной среде. Для другой установки задаётся `CHROMIUM_PATH` и доступный модуль `playwright`.

Backend-тесты используют временную БД и имитацию платёжного API. Проверяют сохранение/повторы, валидацию, закрытые данные, подтверждение суммы, блокировку ненастроенных платежей, проверку успешной оплаты и webhook. Browser-тест сам запускает сервер с временной БД и синтетическими заявками: ширины 320/390/768/1440, навигация, вкладки, поиск, избранное, сравнение, корзина, заявка, кабинет, подтверждение цены и сохранность после перезапуска. Реальные контакты и платежи не используются; временная база удаляется.

## Публичное размещение

Нужен Python-хостинг с HTTPS, постоянным диском для `KWAZAR_DATA_DIR`, резервным копированием SQLite, процесс-менеджером и TLS reverse proxy. Встроенный HTTP-сервер подходит для разработки; перед публичным запуском настроить эксплуатацию и защиту на выбранном хостинге. Статический хостинг без backend не поддерживает заявки и оплату.

Публикация облачной среды сохраняет среду разработки, но не публикует сайт на домене и не заменяет резервные копии данных. Процессы при новой задаче запускаются заново. В репозитории нет пользовательских секретов и БД.

Дизайн и тексты самостоятельные; источники исследования и происхождение ассетов: `RESEARCH.md`.

## Подключение WB через API

В настройках среды добавлено требование секрета `KWAZAR_WB_API_TOKEN` для `content-api.wildberries.ru`. Можно использовать ранее выданный действующий токен с чтением категории «Контент». Подключение из другого GPT автоматически не переносится; в этой сессии инструмента WB и привязки его ключа ранее не было. Значение нужно ввести через защищённые настройки, не в чат, Git или frontend.

После применения секрета:

```sh
python3 /workspace/kazar-site/wb_sync.py
```

Это чтение карточек кабинета, без изменения товаров WB. Скрипт использует `POST /content/v2/get/cards/list` — читающий метод Content API, а не запись карточек. Результат для бренда KWAZAR: описания, характеристики и ссылки на фото в `/workspace/kwazar-data/wb-catalog.json`. В публичные файлы сайта экспорт сам не публикуется: перед интеграцией нужно проверить данные и скачать фотографии. При ошибке или неполной пагинации прежний экспорт сохраняется. Токен не печатается, ответы об ошибках не включают тело ответа API.

Без секрета скрипт завершается с кодом 2 и сообщением о недостающем подключении. Три теста с синтетическими данными проверяют фильтрацию бренда/URL фото, завершённость пагинации и сохранение резервной версии. Реальный API без токена ещё не проверен. Цены, остатки, реклама и заказы WB не запрашиваются — для них при необходимости подключаются отдельные права. Ручной запуск не является фоновой синхронизацией или автоматической публикацией.


## Повторный импорт Excel без API

Установить инструменты импорта, если их ещё нет:

```sh
python3 -m pip install --no-input -r requirements-import.txt
```

Импортировать новую выгрузку владельца:

```sh
python3 import_wb_excel.py /путь/к/выгрузке.zip
```

Поддерживается ZIP с одним .xlsx либо сам .xlsx. Считывается только лист «Товары», бренд KWAZAR или KVAZARLAMP; инструкции других листов не исполняются. Исходный файл не изменяется. Все фото проходят проверку формата; предыдущий `catalog.json` заменяется только после получения всех изображений и сохраняется резервной копией вне публичного checkout в `/workspace/kwazar-data/import-backups/`. Уже проверенные оригиналы повторно не скачиваются. После замены каталога перезапустить backend, чтобы он знал новые артикулы.

Данные XLSX не содержат цен и остатков, поэтому импорт не заполняет их выдуманными значениями. API WB для этого импорта не требуется. Скрипт API также принимает фактическое имя бренда KVAZARLAMP, если позднее будет подключён токен.

## Комплект размещения и резервные копии

Добавлены `Dockerfile`, `compose.yaml`, `deploy/Caddyfile`, `deploy/.env.example` и `backup_store.py`. Порядок переноса, настройки DNS/HTTPS, хранения данных и обновлений — в `deploy/RUNBOOK.md`; источники выбора провайдера — `deploy/HOSTING_OPTIONS.md`.

Локально проверены сборка, Caddy/Compose-конфигурация, 53 товара через прокси, работа приложения без root, сохранение синтетической заявки после пересоздания контейнера и восстановление из проверенной копии. Копии ежечасные, последние 168, в отдельном томе того же VPS. Для защиты от потери всего сервера потребуется отдельное защищённое внешнее хранение. Публичный домен/TLS и реальные платежи не активированы.

Для автономной копии без Docker: `python3 backup_store.py --output-dir /защищённый/каталог`. Скрипт использует SQLite backup API, учитывает активный WAL, проверяет целостность, не копирует ключ владельца и не создаёт пустую базу вместо отсутствующей. Файлы копий содержат конфиденциальные данные заказов и клиентские ключи; не публиковать их.

`GET /healthz` проверяет готовность хранилища, не раскрывая данные. `KWAZAR_TRUST_PROXY=1` включается только при закрытом извне порте приложения за доверенным reverse proxy: тогда ограничение запросов учитывает переданный прокси IP клиента. В прямом dev-запуске этот флаг не требуется.

Новые проверки: `python3 tests/deploy_smoke.py` (изолированный Docker project; нужен Docker Compose 2.24.4+) и unit-тесты backup/health/proxy. Всего серверных/импортных тестов — 17. Деплой на внешний VPS не выполнялся.
